   - id (uuid, PK)

3. **perizinan**
   - id (uuid, PK)
   - userId (uuid, FK -> auth.users)
   - tanggalUtcDate (varchar, YYYY-MM-DD)
   - kategoriIzin (enum: sakit, pergi)
   - keterangan (text)
   - approvalStatus (enum: pending, approved, rejected)
   - fotoUrl (text)
   - createdAt, updatedAt (timestamp)

4. **biodata_siswa**
   - id (serial, PK)
   - nis (bigint, unique)
   - nama (varchar)
   - className (varchar)
   - ... (various fields)

### Client-Side (React)
```

  ↓
src/trpc/react.tsx (httpBatchStreamLink + SuperJSON)
  ↓
/api/trpc/[trpc] (Next.js API Route)
  ↓

  ↓

  ↓
```

```
  ↓

  ↓
```

## 🔒 Security & Best Practices

1. **Protected Routes**: Semua tRPC procedure menggunakan `protectedProcedure`
2. **Input Validation**: Zod schema untuk semua input
3. **SQL Injection Prevention**: Drizzle ORM parameterized queries
4. **Auth Check**: Middleware enforce authentication
5. **CORS**: Configured di tRPC httpBatchStreamLink
6. **Environment Variables**: Validated dengan @t3-oss/env-nextjs

---

## 🐛 Known Issues & Limitations

1. **Geofencing**: Lokasi absensi hanya validasi radius, belum handle GPS spoofing
2. **Bulk Operations**: Bulk delete maksimal sesuai query limit
3. **Export Large Data**: Export besar bisa timeout (consider server-side generation)
4. **Real-time Updates**: Tidak ada WebSocket, perlu refresh manual atau polling

## 📝 Catatan Tambahan

### Path Alias
- `~/*` → `./src/*` (configured di tsconfig.json)
- Contoh: `import { api } from "~/trpc/react"`

### Database Connection
- Menggunakan `postgres` driver (bukan `pg`)
- Connection string di `DATABASE_URL` env variable

### Auth
- Supabase SSR-friendly clients
- User session di middleware
- Protected procedure menambahkan `user` ke context

### API Convention
- Date format: `YYYY-MM-DD` (string)
- Pagination: `limit` & `offset`
- Sort: `asc` | `desc`
- Filter: dynamic dengan Drizzle `and/eq/desc`
